`PullThroughCache` (cluster-scoped singleton `default`, shortname `ptc`) installs Spegel on Talos. Spec: `docs/superpowers/specs/2026-09-25-pull-through-cache-design.md`; plan: `docs/superpowers/plans/2026-09-25-pull-through-cache.md`; live acceptance: `docs/runbooks/pull-through-cache-verification.md`. It is a parallel component (own reconciler, second `Controller` in `main.rs`, same leader lease), not a refactor of the CNI reconciler; extract a shared component framework only when a third component shows what is genuinely shared. kube-fledged pre-warming, an `external` provider and an `aws-ecr` provider are deliberately not built.

**Non-obvious facts (from rendering the real chart, not assumed):**
- The OCI chart tag has **no `v` prefix** (`0.7.4`); `v0.7.4` is only the GitHub release tag and 404s on ghcr.io.
- `helm template` on an `oci://` chart prints `Pulled:`/`Digest:` lines to **stdout**; unstripped they parse as a bogus first manifest. `helm::strip_oci_pull_preamble` removes them; the ignored test `helm::tests::spegel_chart_renders_parseable_manifests_with_our_values` pins it.
- `registries` maps to `spegel.mirroredRegistries` (entries are URLs, `https://docker.io`; see the next bullet), whose default `[]` means **every registry**, so omitting it mirrors private registries too. An explicitly empty list is rejected as ambiguous.
- Spegel's DaemonSet publishes on `hostPort` 30020 (Calico provides hostPort), runs on the pod network and discovers peers through cluster DNS, so it needs the CNI (pod network) and cluster DNS up first. The reconciler applies without waiting for that.
- Node cleanup on delete is a **post-delete Helm hook** (`templates/post-delete-hook.yaml`), and the controller renders with `--no-hooks` (required: rendered hooks would run as live objects at install), so it does not run on delete.
- Running before the CNI (host-network mode) was considered and **dropped**: the chart has no `hostNetwork` value and hard-codes `--bootstrap-kind=dns` against cluster DNS, so it needs a post-render DaemonSet patch plus the HTTP bootstrapper; only nodes after the first would benefit and the cache dies with the cluster. Apply `PullThroughCache` after the CNI is `Ready`.
- `registries` entries must be **URLs** (`https://docker.io`), not bare hostnames: Spegel's `configuration` init container exits 1 with `invalid registry url scheme must be http or https: docker.io` / `invalid registry url path has to be empty: docker.io`. Also, on a **single node Spegel never becomes Ready**: the `registry` container logs `routing table is empty after bootstrapping`, the startup probe returns 500 and it restarts. Peers are needed.
- Failures after validation now write status (Failed with RenderFailed / InvalidManifest / ApplyFailed) and the ledger is checkpointed before applying; see docs/superpowers/specs/2026-09-25-reconciler-status-and-ledger-design.md.
- The Talos node prerequisite (`/etc/cri/conf.d/20-customization.part` with `discard_unpacked_layers = false`) cannot be applied by the controller and cannot be verified by it; `Ready` means manifests applied only.

**Live verification (2026-09-25, one control-plane node, Talos v1.14.0, Kubernetes v1.37.0, containerd 2.3.4, IPv6-only, controller run locally).** Apply and cleanup are verified live: reconcile reached `Ready` in ~10s, the chart rendered 5 objects (6 applied with the namespace), the DaemonSet was admitted and the pod got a Calico pod IP; with URL registries the init container succeeded (via the `helmValues` passthrough, which proved it reaches the DaemonSet); delete cleared the finalizer and removed everything, including the `spegel` namespace, in ~10s. Fail-open was observed with caveats: with the post-delete hook not run, pulling `registry.k8s.io/pause:3.8` (not on the node) succeeded in ~1.5s, as did a pull while the DaemonSet existed, so containerd fell back to upstream; but it was one node, the node's leftover mirror config was not inspected (no Talos API access) and the mirror never served content. **Peer-to-peer serving was NOT verified** (needs at least two nodes), and the Talos machine-config prerequisite was NOT applied. (The IPv6 mirror-target question left open here was answered on the six-node cluster, below.)

**Ledger and failure-status follow-up, live-verified 2026-09-25** (single-node IPv6 Talos cluster, branch controller run locally; spec `docs/superpowers/specs/2026-09-25-reconciler-status-and-ledger-design.md`): (A) an existing `CniInstallation` reconciled with 0 checkpoint writes, stayed `Ready`, pools and pods unchanged. (B) `chartVersion: v0.7.4` on a `PullThroughCache` showed `Failed` / `RenderFailed` with the helm "not found" message within one reconcile (previously an empty status); correcting it logged `checkpointing ledger before applying entries=6` and reached `Ready`. (C) a DaemonSet the API server rejects (`resources.limits.memory: bogus` via `helmValues`) left the namespace, ServiceAccount and Services applied and showed `Failed` / `ApplyFailed` with a 6-entry ledger; deleting the resource then removed everything including the `spegel` namespace (before this change it was left behind). (D) a nonexistent Calico `chartVersion` showed `Failed` / `RenderFailed` on the live `CniInstallation` with its 16-entry ledger preserved and every Calico pod untouched; restoring it returned to `Ready`. Not reproduced live: a CNI first install failing partway (the CNI checkpoint path ran only in steady state, where it correctly writes nothing).

**Peer-to-peer serving and the IPv6 mirror-target bug, live-verified 2026-09-26** (six-node IPv6-only Talos cluster, chart 0.7.4): all six Spegel pods became Ready with 0 restarts, but the first pull test showed NO mirror requests, because containerd rejected the registry's whole `hosts.toml`: `unable to parse server http://fd97:...::227:30021: invalid port ... after host` / `failed to decode /etc/cri/conf.d/hosts/registry.k8s.io/hosts.toml`. Root cause (Spegel source, `main.go`): `args.MirrorTargets[0] = httpx.EncapsulateIPv6Host(args.MirrorTargets[0])` brackets only the FIRST `--mirror-targets` value. Chart 0.7.x passes a hostPort target (`:30020`, first, bracketed) and then a NodePort target (`:30021`, written unbracketed), so on IPv6 the second poisons the whole file and every pull goes straight upstream. No chart value drops that target. Fix in this repo: `pull_through_cache::drop_unbracketed_node_ip_mirror_targets` removes every chart-generated `http://$(NODE_IP):...` target after the first from each DaemonSet container (called after render/parse in `cache_reconciler`); literal `additionalMirrorTargets` are kept, and a sole target is left alone, which is the chart 0.8.x shape (`0.8.0-rc.1` renders a single `:30020` target, so it works without the patch). Verified live with the equivalent manual DaemonSet patch: `hosts.toml` then held the single bracketed target, and pulling `registry.k8s.io/pause:3.8` on worker-1 (`spegel_mirror_requests_total{cache="miss"}`, 3.7s from upstream) and then on worker-2 (`{cache="hit"}`, 0.85s, mirror-success timestamp set) showed a real peer hit. The controller change itself has passed unit tests and a real-chart test but has not yet run against the cluster.

**How to apply:** when bumping the Spegel chart version, re-render it (`helm template ... oci://...`) and re-check `spegel.mirroredRegistries`, `spegel.containerdRegistryConfigPath`, the hostPort, and whether the post-delete hook changed; run the ignored real-chart test.
